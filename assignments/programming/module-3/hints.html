EN.605.631 — Chapter 3 Assignment Hints (Conditional Probability & Independence)

Use these hints to structure your work without jumping straight to final numeric answers. Pair each hint with a quick sketch, a tree/graph, or a short simulation to sanity‑check.

General workflow

  1. Name events clearly and draw a picture (table, tree, or network).
  2. Translate words to symbols: identify unions/intersections, complements, and partitions.
  3. Choose a tool: conditional probability, law of total probability, Bayes, independence tests, or a counting argument.
  4. Validate: simulate a small version and check limiting or symmetry cases.

Problem 1 — Conditioning by enumeration & simulation

What it tests: Computing P(E|F) by counting outcomes when sample points are equally likely; verifying by simulation.
Plan:

  • Write the sample space explicitly (e.g., ordered dice pairs).
  • Count |E ∩ F| and |F|, then take |E ∩ F|/|F|.
  • Cross‑check with a quick Monte Carlo simulation.

Pitfalls: Mixing up “at least one” vs “exactly one”; forgetting order in ordered pairs.

Starter R (skeleton):

set.seed(631)
# Enumerate all ordered dice pairs
Ω <- expand.grid(d1 = 1:6, d2 = 1:6)

# Define events as logical vectors
A <- with(Ω, d1 + d2 == 7)               # example event
B <- with(Ω, d1 == 4 | d2 == 4)          # example conditioning event

# Compute conditional probability P(A | B)
p_hat_enum <- mean(A & B) / mean(B)

# Monte Carlo check
n <- 1e5
d1 <- sample(1:6, n, replace = TRUE)
d2 <- sample(1:6, n, replace = TRUE)
A_sim <- (d1 + d2 == 7)
B_sim <- (d1 == 4 | d2 == 4)
p_hat_sim <- mean(A_sim & B_sim) / mean(B_sim)

Problem 2 — Law of total probability & Bayes in diagnostics

What it tests: Partitioning by a latent state (e.g., “diseased/not”), then updating with Bayes.
Plan:

  • Identify a partition (F_1, \dots, F_n) and an evidence event (E).
  • Use (P(E)=\sum_i P(E|F_i)P(F_i)); then Bayes: (P(F_j|E)=\frac{P(E|F_j)P(F_j)}{\sum_i P(E|F_i)P(F_i)}).
  • Interpret results in terms of false positives/negatives and base rates.

Pitfalls: Using sensitivity/specificity incorrectly; forgetting to normalize posteriors.

Starter R:

# Example structure for diagnostic testing
prior <- c(D=0.01, Dc=0.99)          # replace numbers as needed
sens <- 0.95                         # P(positive | D)
spec <- 0.97                         # P(negative | Dc)
p_pos <- sens*prior["D"] + (1-spec)*prior["Dc"]
post_D_given_pos <- sens*prior["D"] / p_pos

Problem 3 — Independence vs pairwise independence

What it tests: Distinguishing pairwise independence from mutual independence; constructing counterexamples.
Plan:

  • Show pairwise products equal intersections: (P(E_iE_j)=P(E_i)P(E_j)).
  • Check three‑way: (P(E_1E_2E_3)=P(E_1)P(E_2)P(E_3)).
  • If a counterexample is needed, use 3 fair coin flips with events “first=second”, “second=third”, “first=third”.

Pitfalls: Assuming pairwise independence implies mutual independence (it does not).

Starter R:

# Counterexample generator for pairwise but not mutual independence
Ω <- expand.grid(x1=c(0,1), x2=c(0,1), x3=c(0,1))
E12 <- with(Ω, x1==x2)
E23 <- with(Ω, x2==x3)
E13 <- with(Ω, x1==x3)

Problem 4 — Monty Hall: conditional reasoning vs simulation

What it tests: Conditional trees, host behavior assumptions, and simulation to verify “switching” advantage.
Plan:

  • Define host strategy (always opens a goat door, never opens your door, chooses randomly when two goats).
  • Compute (P(win \mid stay)) and (P(win \mid switch)) with a tree.
  • Validate with simulation.

Pitfalls: Ambiguous host behavior; forgetting to condition on the door the host opens.

Starter R:

set.seed(631)
monty_once <- function(host_randomize=TRUE){
  prize <- sample(1:3,1); choice <- sample(1:3,1)
  goats <- setdiff(1:3, prize)
  openable <- setdiff(1:3, choice)
  openable <- intersect(openable, setdiff(1:3, prize))  # goats only
  host <- if(host_randomize) sample(openable, 1) else openable[1]
  stay_win <- (choice == prize)
  switch_choice <- setdiff(1:3, c(choice, host))
  switch_win <- (switch_choice == prize)
  c(stay=stay_win, switch=switch_win)
}
n <- 1e5
res <- replicate(n, monty_once())
p_stay <- mean(res["stay",]); p_switch <- mean(res["switch",])
# cat(p_stay, p_switch, sep="

Problem 5 — Reliability networks under independence

What it tests: Series/parallel systems and complements; using inclusion–exclusion when paths share components.
Plan:

  • For series: multiply component reliabilities. For parallel: compute complement then complement back.
  • If the network has shared components, identify minimal path/cut sets and use inclusion–exclusion or bounds.
  • Simulate by sampling component up/down states and checking connectivity.

Pitfalls: Treating dependent components as independent; double‑counting in unions of events.

Problem 6 — Conditional chains & multiplication rule

What it tests: Breaking complex intersections into a product of conditional probabilities.
Plan:

  • Use (P(E_1\cdots E_k)=P(E_1)\prod_{i=2}^k P(E_i|E_1\cdots E_{i-1})).
  • Model as sequential draws with or without replacement.

Pitfalls: Conditioning on the wrong history; forgetting to update counts without replacement.

Starter R:

# Example skeleton: drawing without replacement
draw_no_replace <- function(N_red, N_white, k){
  # compute P(R1 R2 ... Rk) using a product of conditionals
  probs <- numeric(k)
  R <- N_red; W <- N_white; N <- R + W
  for(i in 1:k){
    probs[i] <- R / N
    R <- R - 1; N <- N - 1
  }
  prod(probs)
}

Problem 7 — Waiting times: geometric distribution

What it tests: Memoryless property and computing P(T>t), P(T=t); comparing theory vs simulation.
Plan:

  • For independent Bernoulli(p) trials, (P(T=t)=(1-p)^{t-1}p).
  • Use memorylessness to simplify conditionals, e.g., (P(T>s+t|T>s)=P(T=t)).
  • Simulate runs to check.

Pitfalls: Confusing geometric “number of trials to first success” with “number of failures before first success”.

Starter R:

set.seed(631)
rgeom1 <- function(n, p){
  # number of trials until first success
  trials <- rgeom(n, prob=p) + 1
  trials
}
# Empirical check
n <- 1e5; p <- 0.3

Problem 8 — Bayes with a partition (toy Naïve Bayes)

What it tests: Posterior computation when features are conditionally independent given a class.
Plan:

  • Write priors P(C_j). For features X_k, use (P(x|C_j)=\prod_k P(x_k|C_j)) (Naïve Bayes).
  • Compute unnormalized posteriors (\tilde{P}(C_j|x)=P(x|C_j)P(C_j)) and then normalize.
  • Compare with a simulation that samples classes then features.

Pitfalls: Forgetting to renormalize; assuming independence uncritically.

Starter R:

# Toy Naive Bayes
prior <- c(S=0.6, H=0.4)     # spam vs ham
theta <- list(
  S = c(O=0.5, F=0.6, M=0.1),
  H = c(O=0.05, F=0.1, M=0.4)
)
x <- c(O=1, F=1, M=0)        # observed features (1/0)

lik <- sapply(names(prior), function(cls){
  pr <- theta[[cls]]
  # Bernoulli likelihoods
  prod(ifelse(x==1, pr, 1-pr))
})
post_unnorm <- lik * prior
post <- post_unnorm / sum(post_unnorm)
